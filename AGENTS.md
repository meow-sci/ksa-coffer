# overview

ksa-coffer is a documentation repository that compiles a corpus of information about creating game mods for Kitten Space Agency (KSA)

# technology

- use OKF for documentation
- use NodeJS 24 compliant TypeScript scripts under scripts/ for scripted tasks.  no transpilation ever applied.  MUST run with NodeJS 24 which can run TypeScript directly.
- use pnpm package manager (the `scripts` workspace package depends on `yaml` for frontmatter parsing)
- the OKF skill scripts (`.claude/skills/okf/scripts/validate_bundle.py`, `build_indexes.py`) are Python 3 with `pyyaml`

# skills

- okf - for authoring documentation in OKF format properly

# instructions

- MUST always keep key instructions and doc files up to date
  - MUST keep AGENTS.md up to date when project level items change: built-in scripts, folder structure changes, etc
- MUST keep project level documentation under docs/ folder using OKF format
- MUST follow [docs/content-conventions.md](./docs/content-conventions.md) when writing anything under content/ (layout, frontmatter pins, lifecycle vocabulary, code references)
- after editing content/, run `python3 .claude/skills/okf/scripts/validate_bundle.py content`, `python3 .claude/skills/okf/scripts/build_indexes.py content` and `node scripts/content_check_refs.ts content`; all must be clean
- after editing ai/catalog/*.yml or any mod overview, run `node scripts/references_build_md.ts` to regenerate REFERENCES.md

# folder structure

- `content/` - the OKF knowledge bundle (root `content/index.md`)
  - `content/mods/<mod-slug>/` - one sub-bundle per reference repo: `overview.md` (type Mod), `features/*.md` (type Mod Feature), `submods/*.md` (type Submod, monorepos only), `index.md`, `log.md`
  - `content/howto/<category>/<group>/<topic>/` - one sub-bundle per how-to topic, grouped one level below the category (groups assigned in `ai/catalog/howto-plan.yml`): `overview.md` (type Game Feature), `<topic>.md` or `<topic>-N.md` (type How-To), `index.md`, `log.md`
- `docs/` - project-level OKF documentation (conventions, pipeline)
- `data/references.yml` - pinned inventory of the reference checkouts under `references/` (git-ignored checkouts)
- `ai/` - orchestration artifacts: `briefs/` (subagent briefs), `catalog/` (per-mod feature catalogs, how-to plan `howto-plan.yml` with `howto-plan-summary.md`, plan parts, per-batch plan excerpts under `batches/`), `reviews/` (critical review reports), `STATUS.md` (progress tracker)
- `attribution/`, `attribution.yml` - license copies and attribution, generated by `scripts/references_check_refs.ts`

# built-in scripts

- `node scripts/references_check_refs.ts [--update]` - check/record reference checkouts in `data/references.yml`, regenerate attribution
- `node scripts/content_check_refs.ts [path ...] [--stale] [--quiet]` - verify `repos`/`game` pins, `sources[]` paths and GitHub blob links in content against the checkouts; `--stale` lists bundles whose pins differ from the checkouts (refresh signal)
- `node scripts/content_crosslink.ts [--dry-run]` - add See-also links from feature pages to the how-to articles that cite them in `demonstrated_by`
- `node scripts/content_howto_related.ts [--dry-run]` - link how-to topic overviews to their `related` topics from `ai/catalog/howto-plan.yml`
- `node scripts/references_build_md.ts [--check]` - regenerate REFERENCES.md from the data file, overviews and catalogs
- `python3 .claude/skills/okf/scripts/validate_bundle.py <dir>` and `build_indexes.py <dir>` - OKF conformance and index generation

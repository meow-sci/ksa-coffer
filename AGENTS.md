# overview

ksa-coffer is a documentation repository that compiles a corpus of information about creating game mods for Kitten Space Agency (KSA)

# technology

- use OKF for documentation
- use NodeJS 24 compliant TypeScript scripts under scripts/ for scripted tasks.  no transpilation ever applied.  MUST run with NodeJS 24 which can run TypeScript directly.
- use pnpm package manager (the `scripts` workspace package depends on `yaml` for frontmatter parsing)
- the OKF skill scripts (`.claude/skills/okf/scripts/validate_bundle.py`, `build_indexes.py`) are Python 3 with `pyyaml`

# skills

- okf - for authoring documentation in OKF format properly
- add-mod - add a new mod repo to the corpus (checkout, bundle, review, how-to integration)
- refresh-data - refresh the corpus after mod or game assembly updates (plan, triage, re-pin, review)

Skills live in `.claude/skills/<name>/` and are mirrored identically in `.agents/skills/<name>/`; edit both.

# instructions

- MUST always keep key instructions and doc files up to date
  - MUST keep AGENTS.md up to date when project level items change: built-in scripts, folder structure changes, etc
- MUST keep project level documentation under docs/ folder using OKF format
- MUST follow [docs/content-conventions.md](./docs/content-conventions.md) when writing anything under content/ (layout, frontmatter pins, lifecycle vocabulary, code references)
- after editing content/, run `python3 .claude/skills/okf/scripts/validate_bundle.py content`, `python3 .claude/skills/okf/scripts/build_indexes.py content` and `node scripts/content_check_refs.ts content`; all must be clean
- after editing ai/catalog/*.yml or any mod overview, run `node scripts/references_build_md.ts` to regenerate REFERENCES.md

# folder structure

- `content/` - the OKF knowledge bundle (root `content/index.md`)
  - `content/mods/<mod-slug>/` - one sub-bundle per reference repo: `overview.md` (type Mod), `features/*.md` (type Mod Feature), `submods/*.md` (type Submod, monorepos only), `index.md`, `log.md`
  - `content/howto/<category>/<group>/<topic>/` - one sub-bundle per how-to topic, grouped one level below the category (groups assigned in `ai/catalog/howto-plan.yml`): `overview.md` (type Game Feature), `<topic>.md` or `<topic>-N.md` (type How-To), `index.md`, `log.md`
- `docs/` - project-level OKF documentation (conventions, pipeline, site, skill build)
- `data/references.yml` - pinned inventory of the reference checkouts under `references/` (git-ignored checkouts)
- `ai/` - orchestration artifacts: `briefs/` (subagent briefs, incl. `REFRESH_BRIEF.md`), `catalog/` (per-mod feature catalogs whose `ref:` is the mod's triage baseline, `game.yml` the game triage baseline, how-to plan `howto-plan.yml` with `howto-plan-summary.md`, plan parts, per-batch plan excerpts under `batches/`), `refresh/` (`triage.yml` benign-change ledger, tracked; `plan.md`/`plan.json` refresh reports, git-ignored), `reviews/` (critical review reports), `STATUS.md` (progress tracker of the initial build)
- `site/` - Astro Starlight static site (pnpm workspace package `site`) that renders `content/` in place (no copy); config in `site/astro.config.ts`, loader in `site/src/content.config.ts`, OKF helpers in `site/src/lib/okf.ts`, link-rewriting remark plugin in `site/src/plugins/`, contextual sidebar and dated hero download link in `site/src/routeMiddleware.ts`; home-page freshness in `site/src/components/ContentStatus.astro` and skill download in `SkillDownload.astro`, both reading the git-ignored `site/public/downloads/ksa-modding.json` manifest through `site/src/lib/skill-download.ts`; archives are named `ksa-modding-YYYY-MM-DDTHHmmssZ.tar.gz` with `ksa-modding/` inside; deployed by `.github/workflows/site-deploy.yml` to https://meow.science.fail/ksa-coffer/
- `attribution/`, `attribution.yml` - license copies and attribution, generated by `scripts/references_check_refs.ts`
- `dist/` - git-ignored build outputs (`dist/skill/ksa-modding/` Agent Skill)

# maintaining the corpus

The corpus pins exact commits everywhere (`repos[].ref` and `game.ref`/`game.build` in every concept's
frontmatter, pinned GitHub blob links with `#Lx-Ly` anchors, snippet headers `// path Lx-Ly`). A refresh
recomputes everything from those pins with deterministic scripts and spends agent effort only where a
real code change overlaps a cited line range. Follow these steps in order; stop as soon as a step says
there is nothing to do. Use Sonnet-class subagents at high effort for refresh work.

1. **Fetch.** `node scripts/references_pull.ts` (fast-forwards every checkout and the game assemblies;
   anything flagged `!` needs a manual look). New mod: `git clone <url> references/<RepoName>` first.
2. **Record.** `node scripts/references_check_refs.ts --update` (records new HEADs and new checkouts in
   `data/references.yml`, refreshes attribution).
3. **Plan.** `node scripts/content_refresh_plan.ts --out ai/refresh/plan.md --json ai/refresh/plan.json`.
   Read only `ai/refresh/plan.md`; it is the whole worklist. If every count is zero and every section
   says `none`, the corpus is current: stop.
4. **Drift** (plan section "Inventory drift"):
   - NEW MOD (repo without a bundle): run `ai/briefs/MOD_BUNDLE_BRIEF.md` then `ai/briefs/REVIEW_BRIEF.md`
     for it (writes `content/mods/<slug>/` and `ai/catalog/<slug>.yml`, whose `ref:` becomes its
     baseline), then integrate it into how-tos (step 9).
   - Bundle without a repo entry: the repo was removed; set `status: deprecated` on its overview and
     say why in its `log.md`. Never delete pages others link to.
5. **Triage changes, not pages** (plan section "Review work, grouped by change"). Each `h-...` (diff
   hunk) or `f-...` (changed file cited without line ranges) is listed once with its diff and the
   pages it affects, most-cited first. Read the diff; if it cannot change anything those pages claim
   (logging, profiling, telemetry, comments, version strings, an unrelated branch), record it:
   `node scripts/content_refresh_plan.ts --benign <id>,<id>,...` (ledger: `ai/refresh/triage.yml`;
   add a short reason after each id). Decompiler noise (embedded source line numbers, renumbered
   compiler-generated names) is already ignored automatically. When unsure, do not mark benign.
6. **Re-pin.** `node scripts/content_refresh_plan.ts --repin`. Every page whose cited ranges are
   untouched (or touched only by benign changes) moves to the new commit; line anchors and snippet
   headers are remapped through the diff, `game.build` is updated. Then
   `node scripts/content_check_refs.ts content --quiet` must report 0 errors (stale = pages still in review).
7. **Review the rest.** Re-run the plan; dispatch the remaining review pages to subagents with
   `ai/briefs/REFRESH_BRIEF.md`, batched by repo or by change id (about 15-25 pages per agent). Each
   agent finishes a page with `--accept content/<page>.md` and fixes only the ranges it prints. Then
   the plan section "How-to pages depending on reviewed features" lists how-tos to re-read.
8. **Untriaged upstream code** (plan section "Untriaged upstream changes"): per mod repo, paths changed
   since the catalog baseline that no page cites. If any is a new reusable mechanism, run
   `MOD_BUNDLE_BRIEF.md` scoped to those paths (new feature pages + catalog entries) and `REVIEW_BRIEF.md`,
   then integrate (step 9). Then `--ack <RepoName>` to move that repo's baseline to HEAD. For the game,
   section "Game builds since the game baseline" prints each build's changelog: update the lifecycle
   reference or how-tos if an engine change warrants it, then `--ack game`.
9. **How-to integration** (only when features were added): `content_refresh_plan.ts --coverage` lists
   feature pages no how-to cites. For each, either add an approach to an existing topic (edit its entry
   in `ai/catalog/howto-plan.yml`, write the article per `ai/briefs/HOWTO_BUNDLE_BRIEF.md`) or plan a new
   topic in the right `<category>/<group>/`; then review per `REVIEW_BRIEF.md` (how-to section).
10. **Finish.** `node scripts/content_crosslink.ts`, `node scripts/content_howto_related.ts`,
    `python3 .claude/skills/okf/scripts/build_indexes.py content`, `python3 .claude/skills/okf/scripts/validate_bundle.py content`,
    `node scripts/content_check_refs.ts content`, `node scripts/references_build_md.ts`; add a dated
    `**Update**` entry to each touched bundle's `log.md` and one summary entry to `content/log.md`;
    rebuild the skill and site if they are being published. Done when
    `node scripts/content_refresh_plan.ts --check` exits 0 and all validators are clean.

Rules: never edit a pin, anchor or snippet header by hand to "make the checker pass"; go through
`--repin`/`--accept` so the remapping stays consistent. `--ack` only after triaging, because it
discards the untriaged-change signal for that repo. If a pinned commit is missing locally (status
`unknown`), fetch full history (`git -C <checkout> fetch --unshallow` or `--all`) and re-plan.

# built-in scripts

- `node scripts/references_pull.ts [--dry-run] [--only NAME,...] [--no-game]` - fetch every reference checkout and the game assemblies, fast-forward to upstream, clone missing ones, unshallow shallow ones; never edits data or content
- `node scripts/references_check_refs.ts [--update]` - check/record reference checkouts in `data/references.yml` (adds new checkouts), regenerate attribution
- `node scripts/content_refresh_plan.ts [--out F] [--json F] [--check] [--coverage] [--benign IDS] [--repin] [--accept PAGES] [--ack REPOS|game|all]` - the refresh planner: classifies every concept as current / repin / review / unknown from line-level diffs of the code it cites, groups review work by diff hunk, reports untriaged upstream changes, game changelogs and inventory drift, and performs the mechanical rewrites (see "maintaining the corpus")
- `node scripts/content_check_refs.ts [path ...] [--stale] [--quiet]` - verify `repos`/`game` pins, `sources[]` paths and GitHub blob links in content against the checkouts; `--stale` lists bundles whose pins differ from the checkouts (refresh signal)
- `node scripts/content_crosslink.ts [--dry-run]` - add See-also links from feature pages to the how-to articles that cite them in `demonstrated_by`
- `node scripts/content_howto_related.ts [--dry-run]` - link how-to topic overviews to their `related` topics from `ai/catalog/howto-plan.yml`
- `node scripts/references_build_md.ts [--check]` - regenerate REFERENCES.md from the data file, overviews and catalogs
- `node scripts/skill_build.ts [--out dist/skill] [--tarball <base.tar.gz>]` - compile content/ into the Agent Skill at dist/skill/ksa-modding/ (git-ignored); `--tarball site/public/downloads/ksa-modding.tar.gz` inserts the build's UTC timestamp before `.tar.gz` and writes `ksa-modding.json` with the filename, build time, last content commit time and all pinned KSA builds; MUST run before `pnpm --filter site build`. Use full Git history for the content date (CI sets `fetch-depth: 0`); without history, the latest OKF generated/verified time is used. The archived directory stays `ksa-modding/`.
- `pnpm --filter site dev` - local dev server for the docs site; `pnpm --filter site build` - build the docs site to `site/dist` (needs the skill tarball, see above); `pnpm --filter site check-links` - verify every internal href in `site/dist` resolves
- `python3 .claude/skills/okf/scripts/validate_bundle.py <dir>` and `build_indexes.py <dir>` - OKF conformance and index generation

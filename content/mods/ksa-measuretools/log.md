## 2026-10-10
* **Update**: Independent review against KSA-MeasureTools aed7f87, StarMap 4dc60f8 and build 2026.10.10.5554. Timing: [part-anchor re-homing](features/part-anchor-rehoming.md) and [editor measuring](features/editor-measuring.md) dropped `editor:on-frame`/`editor:draw-ui` (no mod code runs in `Editor.OnFrame` or `Editor.OnDrawUi`; the editor work runs in the `OnMouseButton` prefix and `StarMapAfterGui`), and re-homing now names where each ownership change is applied (staging decouples in `InputEvents.ApplyInputEvents`, contact docking and part failures in `ApplyVehicleSolvers`, editor exit in `PrepareFrame`) instead of "a decoupler applied in ApplyVehicleSolvers". The [overview](overview.md) note on the source comments said the AfterGui preview sees `CursorHoverEligible` from the previous frame; `OnFrameViewports` clears it before AfterGui, so it reads false (the part picker is the previous frame's). [Part picking](features/part-mesh-raycast-picking.md) no longer calls the stale picker harmless (a null stale picker skips the mesh scan for one preview pick) and no longer says only the editor writes `Part.Asmb2ParentAsmb`. [Click capture](features/click-capture-mouse-prefix.md) and [cursor unprojection](features/cursor-unprojection-and-construction-plane.md) now state that inside `PollEvents` the camera matrices and `Cursor` position are last frame's while a following camera's position is live; the bound-input test is described as an approximation of `MouseBound && DispatchKeyEvent`; `MapController` also clears its rotate flag in `OnSwitchOff`. Unload: [resilient patching](features/resilient-patching-and-diagnostics.md) and the overview now say StarMap's id-less `UnpatchAll()` runs before `StarMapUnload`, so the mod's `UnpatchAll(id)` is a no-op; `PatchAll` is not all-or-nothing; the menu postfix has no `try/catch`; the perf-scope list matches the code. [Palettes](features/color-palettes-persistence.md) now verify `Assembly.Location` against StarMap's `ModAssemblyLoadContext`. Smaller fixes: menu hook also fires in secondary viewports' bars, overlay notes that `viewport.Position` is refreshed after AfterGui, face-angle NaN wording, orbit-pick stock usage, several decomp line anchors. Catalog `game_types` synced with frontmatter and two generic howto topics added. The [game loop reference](../../howto/getting-started/lifecycle/game-loop-and-lifecycle/overview.md) gained the hover-state and mouse-latch timing facts.

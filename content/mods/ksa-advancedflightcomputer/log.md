* **Update**: How-to review (build 2026.10.10.5554 `PhysicsBubble.cs` L793-L796, `Program.cs` L2277-L2281). [Split a maneuver into passes with a forward-chained flight plan](features/multi-pass-burn-splitting.md) said the stock `SequencePerformanceList` is filled by `JobSystems.NearestOrbitAndPerformanceWorker`; that worker's `SequencePerformanceJob` targets the vehicle editor's list, and the controlled vehicle's list is recomputed by `PhysicsBubble` on the vehicle worker while the Sequence or EngineControl gauge canvas is enabled, so the page now says that.
* **Update**: How-to review (build 2026.10.10.5554 `Orbit.cs` `CreateFromStateCci` L1611-L1630). [Set apse, match and set inclination](features/apse-and-inclination-quick-tools.md) said the stock `Orbit.Inclination` is measured against the ecliptic and that CCI +Z is the ecliptic normal. `Orbit.Inclination` and LAN are measured against CCI +Z, the parent body's pole (`acos(h.Z / |h|)` of the CCI angular momentum), so the mod's `Ecliptic` option is really the parent's equatorial plane and its `Equatorial` option (CCE +Z carried to CCI) is the ecliptic; the page now says so and flags the mod's swapped labels and misleading code comment.
* **Update**: Game-loop reference consistency review (build 2026.10.10.5554 `PhysicsBubble.cs` L793-L796, `ResourceGroups.cs` L15, `GaugeCanvas.cs` L143; StarMap 4dc60f8 `StarMap.Core/StarMapCore.cs` L31-L35). [Stage model from the staging simulator](features/stage-model-from-staging-simulator.md) said the game recomputes the controlled vehicle's list on the vehicle worker "only while the Staging window (`ResourceGroups.IsOpen`) or the engine-control gauge is open". `ResourceGroups.IsOpen` is `Program.SequenceCanvas.Enabled`: both are gauge canvases, and both start enabled, so with the default UI the worker recomputes the list on every vehicle step, as the game-loop reference states; the paragraph now says so and `ResourceGroups.cs` and `GaugeCanvas.cs` were added to `sources`. [Warn-once logging](features/warn-once-logging-and-diagnostics.md) presented the `LogHelper.Reset` ordering in `[StarMapUnload]` as suppressing transpiler re-runs caused by the mod's own `UnpatchAll`; it now notes that StarMap's id-less `UnpatchAll()` has already removed every patch before `[StarMapUnload]`, so the mod's call finds nothing (matching [feature-gated patch sets](features/feature-gated-patch-sets.md)).

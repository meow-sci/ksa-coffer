## Compendium

- Upstream: <https://github.com/meow-sci/Compendium> (MIT), pinned at `62cfbe7aafabc58cf71f7c6d618d0c5ece7c504c`
- Bundle: [content/mods/compendium/overview.md](content/mods/compendium/overview.md)
- Loader: starmap, mod id `Compendium`
- Celestial encyclopedia window that joins a cross-mod JSON catalog with the live star-system tree and, through Harmony patches on the navball, gauges and flight computer, lets fixed stars and barycenters act as navigation-only targets
- Features: 17 across ui (5), flight-and-orbits (5), celestials (2), assets (1), rendering (1), patching (1), persistence (1), testing-and-tooling (1)
- Notable techniques:
  - [Cross-mod JSON catalog](content/mods/compendium/features/cross-mod-json-catalog.md) - Scans every JSON file in the mod folders beside its own (one mods root) at immediate load, keeps those with a CompendiumJson marker, keys entries by system or root prefix and body path, loads its own files first and records other mods' keys as overrides.
  - [Navigation-only root targets](content/mods/compendium/features/root-navigation-targets.md) - Session-only navigation targets for fixed stars and root barycenters: ConditionalWeakTables keyed by Vehicle and by the shared BurnPlan, a ConcurrentQueue of UI requests drained in a prefix on InputEvents.ApplyInputEvents, and prefixes on Vehicle.SetTarget and Universe.UnsetTargetCommand that keep native targets authoritative.
  - [Navball target marker and TGT frame for a target without an orbit](content/mods/compendium/features/navball-target-marker-and-tgt-frame.md) - Transpilers replace the single NavigationTarget.Create call in Vehicle.UpdateNavBallMarkers and UpdateNavballData with a mod method (ldarg.0 appended, labels and blocks preserved, exactly-one check) and rewrite one Target null test in four methods to include the side target; a postfix enables the Dock frame.
  - [Flight-computer attitude tracking against a root target](content/mods/compendium/features/flight-computer-root-attitude-tracking.md) - Prefix with __state and a restoring finalizer on FlightComputer.ComputeControl inject a synthesized NavigationTarget into the solver thread's ref readonly navigation struct only for Toward/Away or Dock-frame hold, looked up by the BurnPlan the solver's flight-computer copy shares; IsDisabled/Hovered patches enable the native buttons.

## gatOS

- Loader: starmap, mod id `gatOS`, targets KSA 2026.9.22.5482
- A KSA mod that boots a real Alpine Linux in a QEMU microVM beside the game, exposes live telemetry and controls as a 9P /sim filesystem plus HTTP, MQTT, MCP and serial APIs, and adds programmable camera, paint, decal, audio and physics features on top
- Features: 45 across external-io (15), rendering (8), getting-started (3), vehicles-and-parts (3), testing-and-tooling (3), flight-and-orbits (2), physics (2), camera (2), persistence (2), patching (1), celestials (1), shaders (1), audio (1), ui (1)
- Notable techniques:
  - [Compile-gated game seam](content/mods/gatos/features/compile-gated-game-seam.md) - Splits the mod class into a game-free half and a Game/ half compiled only when KSA.dll exists, joined by partial methods that vanish without the game assemblies.
  - [Frame hooks with an F2-proof fallback](content/mods/gatos/features/frame-hooks-and-f2-fallback.md) - Runs all per-frame game-thread work from a main-viewport GameViewport.OnFrame prefix plus StarMapBeforeGui/AfterGui, with StarMapAfterOnFrame standing in when F2 hides the HUD and skips the GUI hooks.
  - [Solver-phase drain for flight computer setpoints](content/mods/gatos/features/solver-phase-command-drain.md) - Drains flight computer setpoints, refills and teleports in a Priority.First prefix on Universe.ExecuteNextVehicleSolvers, the window between apply and the next FlightComputer snapshot.
  - [Game-thread command queue](content/mods/gatos/features/game-thread-command-queue.md) - All external writes become immutable SimCommands enqueued by transport threads and drained, routed and executed on the game thread in Frame or Solver phase, returning errno-style results.
  - [HTTP /v1 API server](content/mods/gatos/features/http-v1-api-server.md) - A raw-TcpListener HTTP/1.1 server in the game process serving JSON snapshots, SSE, long-poll, OpenAPI, a per-leaf /sim mirror and a generic command endpoint.
  - [MCP server for AI agents](content/mods/gatos/features/mcp-server-for-agents.md) - A stateless Streamable HTTP MCP endpoint built on ModelContextProtocol.Core with a hand-rolled HTTP adapter, exposing logical resources and control tools for AI agents.
  - [9P2000.L server in C#](content/mods/gatos/features/ninep-server-in-csharp.md) - A from-scratch 9P2000.L server and VFS in C# that the Linux guest mounts as /sim, with inline metadata handling, pooled buffers and a confined host-folder passthrough.
  - [purrTTY custom shell contract](content/mods/gatos/features/purrtty-custom-shell-contract.md) - Registers a custom shell with purrTTY by importing its exported contract assembly through an optional StarMap ModDependency, sharing one registry, with vendored fallbacks when purrTTY is absent.
  - [QEMU microVM as a game child process](content/mods/gatos/features/qemu-microvm-host-process.md) - Boots and supervises a QEMU VM from a mod with an async state machine, per-OS accelerator ladders with TCG fallback, an SSH readiness probe and a QGA-QMP-kill shutdown ladder, all off the main thread.
  - [The /sim file models](content/mods/gatos/features/sim-filesystem-file-models.md) - Defines synthetic file types that make Unix tools work on live data under Linux netfslib rules: memoized sensors, growing-log streams, blocking event and alarm files, and errno-returning control files.
  - [Host-guest transport over slirp TCP](content/mods/gatos/features/slirp-tcp-host-guest-transport.md) - All host-guest channels are TCP over QEMU user networking, with host ports passed on the kernel command line and guest supervisors that remount on failure.
  - [Telemetry sampler and snapshot store](content/mods/gatos/features/telemetry-sampler-snapshot.md) - A rate-limited game-thread sampler builds an immutable SimSnapshot of all vehicles and bodies and publishes it with one volatile swap that transport threads read lock-free.

## KittenExtensions Continued

- Upstream: <https://github.com/AMPW-german/KittenExtensions> (MIT), pinned at `b52467541a4fda3c3771eb2c157ed7574f9e2d7c`
- Bundle: [content/mods/kittenextensions/overview.md](content/mods/kittenextensions/overview.md)
- Loader: starmap, mod id `KittenExtensionsContinued`
- Foundational StarMap library mod that runs XPath patches over one combined XML document built from every installed mod's data files and lets other mods register new XML asset types, by redirecting the game's XmlLoader calls and extending its XmlSerializer overrides
- Features: 10 across assets (3), testing-and-tooling (2), ui (2), getting-started (2), patching (1)
- Notable techniques:
  - [Combined GameData XML document](content/mods/kittenextensions/features/gamedata-document.md) - Before any mod XML is deserialized, a ModLibrary.PrepareAll prefix parses every manifest mod's mod.toml with Tomlet and imports its planet mesh, system, asset and patch files into one in-memory Root/Mod document with RelPath on each file root, then runs every Patch in manifest order; disabled mods are included.
  - [XML patch files and XPathPatch operations](content/mods/kittenextensions/features/xpath-patch-operations.md) - Patch files hold Copy (Pos Replace/Append/Prepend/Before/After), Merge (_MergeId, _MergePos), Delete, If/IfAny/IfNone, With and SetVar operations whose XPath 1.0 paths are evaluated from Root; operations run in manifest then document order and may rewrite later patches.
  - [XmlLoader call-site redirect](content/mods/kittenextensions/features/xmlloader-call-site-redirect.md) - A HarmonyTargetMethods transpiler on four Mod loader methods replaces each constructed XmlLoader.Load<T> operand with XmlPatcher.Load<T>.MakeGenericMethod(T), which reads the file node from the patched document through an XmlReader with an override-aware serializer; LoadEditorTagDefinitions and LoadPlanetRandomHeightmaps stay stock.
  - [Custom XML asset types via KxAsset attributes](content/mods/kittenextensions/features/custom-xml-asset-types.md) - A Program.Main prefix scans AssemblyLoadContext.All for assemblies that define their own KittenExtensions.KxAssetAttribute or KxAssetInjectAttribute, matches attributes by full name, validates member types, adds XmlElement mappings to XmlHelper.AttributeOverrides, rebuilds every cached serializer and overwrites the GameSaves and VehicleSaves serializer backing fields with UnsafeAccessor.
  - [Patch debug stepper](content/mods/kittenextensions/features/patch-debug-stepper.md) - A debug = true key on the KittenExtensionsContinued manifest entry saves the unpatched document to root.xml and blocks startup in an ImGui popup with Run All, Step, Step Over and Step Out, an action tree with target and source XPath results, an XPath tester and a live document tree.

  - [Plan a deorbit to a landing site and let stock Auto fly the node](content/mods/ksa-advancedflightcomputer/features/deorbit-landing-planner.md) - A time-sliced Lambert search to an approach point uprange of a rotating site, run as a C# iterator under a per-step and total work budget, then a stock maneuver node whose ignition timing stock computes before AFC arms Auto, followed by braking re-planned from the measured orbit
  - [Measure a vehicle's drag table by calling the game's force function on a state copy](content/mods/ksa-advancedflightcomputer/features/drag-table-measurement.md) - Copy the vehicle's physics state structs, set the airspeed per sample, call the static PhysicsStates.ComputeDerivatives with dt 0 and no thrusters, and fit Cd and CL over Mach and angle of attack, so planners use whatever drag model is active, including aero mods
  - [Feature-gated Harmony patch sets with rollback](content/mods/ksa-advancedflightcomputer/features/feature-gated-patch-sets.md) - One Harmony instance per feature, validated before patching and rolled back on failure, so a game update disables one feature instead of the whole mod
  - [One ComputeControl postfix as an actuator command sink](content/mods/ksa-advancedflightcomputer/features/flight-computer-command-sink.md) - A single postfix on FlightComputer.ComputeControl runs every mod-owned actuator writer on the vehicle worker and merges their wake and off-rails requests into the stock output

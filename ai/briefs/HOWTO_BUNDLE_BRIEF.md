mod: "how do I draw lines on the sky", "how do I add a part with a GLB model", "how do I run code at a
safe point relative to the physics step". When several mods solve it differently, each solution is a
numbered article and the topic overview compares them.

## Deliverables per topic

```
content/howto/<category>/<group>/<topic-slug>/
  index.md                      generated by build_indexes.py
  log.md                        Creation entry
  overview.md                   type: Game Feature
  <topic-slug>.md               type: How-To            (single approach)
  <topic-slug>-1.md, -2.md ...  type: How-To            (several approaches, numbered as in the plan)
```

`overview.md`: what the game system or problem is; `## Engine background` (the decompiled types and
the frame/physics phases involved, with pinned links); `## Approaches` table (article link, mod,
technique, lifecycle, trade-off); `## See also`. Frontmatter: `type: Game Feature`, `topic`, `category`, `group`,
`approaches` (count), `game_types`, `lifecycle`, `demonstrated_by` (mod feature concept ids), `tags`,
`generated`, `status`, `repos` (union), `game`, `sources`.

`<topic-slug>[-N].md`: intro (outcome, prerequisites such as StarMap, Harmony, KittenExtensions, which
mod demonstrates it); `## Background: how the game does it`; `## Lifecycle and timing` (where the code
must run and why, mapped to the vocabulary); `## Steps` (numbered; each step has code, verbatim from the
mod or clearly labelled `// adapted from <path>`; link the original); `## Complete example` (the mod
files, with links); `## Variations and gotchas` (version notes, failure modes, what breaks on game
updates); `## See also` (the sibling approaches, the mod feature concepts, related topics). Frontmatter:
`type: How-To`, `topic`, `category`, `group`, `approach` (omit for single), `difficulty`, `prerequisites`,
`demonstrated_by`, `techniques`, `game_types`, `lifecycle`, `hooks`, `tags`, `generated`, `status`,
`repos`, `game`, `sources`.

Write for a competent C# developer who has never modded KSA. Every step must be actionable: what file to
create, what attribute to use, what game type to call, what to expect in the log. Prefer verbatim mod
code over invented code; when you adapt, keep it minimal and compilable against the named game types.
